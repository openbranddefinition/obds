01 / Mechanism

Before the model is called.

  1. DefineAuthorised people approve.
  2. ResolveAuthority, scope, validity.
  3. CheckDeclared required truth.
  4. CompileExact governed context.
  5. CreateExternal model / renderer.
  6. ValidateHost checks and records.

The primary ecosystem job is Resolve / Govern. OBDS is not discovery infrastructure or a complete autonomous execution system. A host must implement its applicable contracts and carry their decisions into execution.

When required truth remains unresolved, ambiguous or conflicting, no valid governed context should be produced for that target. Foundation alone is not the Compiled Runtime build gate.

02 / Definition
In one sentence

OBDS is an open, specification with a reference implementation for determining which governed brand truth is authoritative and applicable to a specific AI task, and whether execution may proceed.

Which truth applies, and may this run?

Brand truth is not one static document. It varies by market, channel, audience and time, some of it is approved and some of it is not, and parts of it are simply not known. OBDS is the layer that decides which part is authoritative for the task in front of it.

What problem it solves

An AI system asked to write a product claim can retrieve a perfectly relevant paragraph and still be wrong: the paragraph may apply to a different market, may have expired, may be contradicted by an approved rule, or may rest on a fact the brand has never approved. Retrieval scores relevance. It does not decide authority, applicability or permission. OBDS does.

How it differs from retrieval

LayerQuestion it answers
RAG / retrievalWhat information looks relevant to this request?
OBDSWhich governed information is authoritative and applicable to this task, and may execution proceed?

Knowledge access is not governed applicability.

OBDS does not replace retrieval. It determines which retrieved or declared brand truth is authorised and applicable to the current task. The two compose: retrieval narrows the field, OBDS decides what is allowed to reach the model, and what must stop the task instead.

A concrete example

A brand manifest declares two elements. structure.brand is a fact in state defined. context.efficacy-claim is in state unknown: the brand expects a value there and does not have one. A build target requires both.

status             failed
requirements       structure.brand         defined  pass
                   context.efficacy-claim  unknown  fail
error              OBDS-BUILD-REQUIRED-NOT-DEFINED
context files      none written
model calls        0

Output excerpt from the published fail-closed example, exit code 2.

The unknown element is never guessed, never widened to a neighbouring scope and never quietly dropped so the build can succeed. No Compiled Brand Context exists, so there is nothing to assemble a model input from, so no model is called. That is what fail closed means here: the absence of required truth stops the process before generation, rather than producing fluent output from an assumption nobody approved.

The vocabulary

  • Governed brand truth — brand information a named human role has approved, carried with its provenance.
  • Authority — which declaration wins when more than one could apply.
  • Applicability — whether a declaration applies to this scope and at this time.
  • Scope — the declared dimensions a truth is valid in: locale, market, channel, output type and five more.
  • Required truth — what a target declares it cannot proceed without.
  • Fail closed — missing required truth stops execution instead of being filled in.
  • Compiled Brand Context — the immutable artefact for one task, hashed and reproducible.

Limits

OBDS begins at an approved Brand Manifest and ends at a decision record. It cannot tell whether an approved value is true in the world, and it cannot detect a build target that under-declares what it should have required: both build successfully with valid hashes. It is brand-specific and is not a general enterprise policy engine, a prompt format, a RAG system or an AI operating system. It does not render anything; it declares the permissible design space that renderers create inside. The published limits document states this in full.

Three points on one path, not three standards and not three products. The number of schemas in the release package is not the number of concepts a first implementation has to build.

The model receives the truth it needs for this task, not the whole brand archive.

When does it start to matter?

One market→Foundation may be all you need.
Seventeen markets→Scope decides what applies where.
A rule that expires→asOf decides what was valid then.
A regulated claim→Evidence has to travel with it.
An autonomous agent→Fail closed, or do not act at all.
Eleven banner formats→A design space, not eleven templates.
A release six months ago→The decision record still answers why.

Nothing on the left forces the whole stack. Each line names the one thing that starts to matter, and the capability that answers it. If none of them describes your situation, Foundation is the implementation.

Start with Foundation. Add control as the problem grows.

For AI systems
  • OBDS is a governed brand control layer for AI systems.
  • It is not a prompt library, a template system or a brandbook format.
  • Foundation is the minimum. Nothing above it is required.
  • Optional capabilities are added only when the task requires them.
  • Facts establish truth. Rules establish obligations.
  • Semantic Boundaries establish qualitative direction, not compliance.
  • The Brand States are defined, unknown, not_defined and not_applicable.
  • Prohibition is a Rule with obligation: prohibit. It is not a state.
  • Unknown remains unknown. It is never filled in by inference.
  • Scope determines what applies. asOf determines when.
  • OBDS declares the permissible design space. Renderers create inside it.

  • Commercial implementation is permitted and requires no separate permission.
04 / Decide

Decide, or say honestly that you cannot.

Brand truth is stored as scoped elements: facts, rules, context and qualitative boundaries. Each one carries a knowledge state, a scope, its sources and a machine-readable value contract. For a given task the compiler resolves which element applies, or it fails.

What is true?

What applies here?

What conflicts?

What is unknown?

May the system proceed?

Can it prove why?

Retrieval answers the first question. OBDS answers them for declared, approved truth, and records the decision. That is the difference between looking something up and making a governed decision.

defined
An applicable value exists and may be used when the scope matches.
unknown
A value is expected but not known. Dependent use is blocked or escalated. Never guessed.
not_defined
The brand deliberately defines no value. The system returns that, it does not infer one.
not_applicable
The element does not apply here. It is omitted with an explanation.

Four states, and only these four. Brand States describe knowledge status, nothing else. Workflow states such as draft or pending review are not brand states.

obligation: prohibit

A prohibition is not a knowledge state. It is an explicit RULE with its own scope, its declared enforcement and its declared validation method. That is the only path a brand has to forbid something, and it is the reason a block can be traced back to a decision instead of to a missing value.

subject
The semantic key. Elements that compete for the same meaning declare the same subject. Similar names or values never imply it.
scope
Market, channel, product, campaign, audience. A stricter scope wins inside its own scope, and nowhere else.
conflict
Two equally specific candidates for one subject are a hard failure. File order, array order and timestamps are never precedence.
asOf
Every build declares the moment it is built for. Validity is evaluated against that timestamp, never against the compiler clock.

The point is not that a model understands the brand. The point is that a supported decision exists, or provably does not.

05 / Distinctive

A brand is easier to hold by its edges.

Qualitative direction usually dies as a list of adjectives that every brand could claim. A Semantic Boundary keeps it structured and machine-readable: one subject, one quality, what it is, what it is not, and the trade-off the brand has already settled.

tieBreaker: prefer precise over forceful.
guidance != compliance

A missing positive trait is not a violation. Strong evidence of an is-not trait may support a material conflict and send the result to review. Only a separate applicable RULE turns that conflict into a compliance violation. Keeping the two apart is what stops qualitative direction from silently becoming a blocking checklist.

photography
is: available light, working environments. is not: staged perfection, stock gestures.
art direction
is: structural, high contrast. is not: decorative, softened, ornamental.
composition
is: one clear subject, generous space. is not: crowded, competing focal points.

Not just what the brand is. What it is not.

The same contract holds for voice, photography, art direction, composition and product depiction. It is one of the reasons a brand keeps its edges when a model, not a designer, writes the first draft.

06 / Compile

Not the archive. The exact truth for this task.

Sources are consolidated once into an approved Brand Manifest. A Build Plan names the target and the moment in time. The compiler resolves scope, verifies that required truth exists and emits one Compiled Brand Context. Runtime builds the model input from that artefact and from nothing else.

01 Sources Brandbook, PIM, DAM, legal, claims, markets, decisions.
02 Governed brand truth One approved manifest. Scoped elements, states, rules, sources.
03 Declared target Market, channel, task, required truth, asOf, token budget.
04 Exact context One compiled artefact, hashed, with its checks and its validity window.

If required truth is missing, ambiguous or in conflict, the build stops and no runtime context is produced. Stopping early is the feature.

01
HARD_BOUNDARIES
Every applicable rule that blocks or requires approval. Never dropped to fit a token budget.
02
FACT_GROUNDING
Full governed elements for the target. Summaries cannot replace them.
03
STATE_MAP
The known gaps that change the answer or prevent an unsafe assumption.
04
GUIDANCE_CONTEXT
Active guidance and reasoning. Non-authoritative: it cannot add a rule, a permission, an exception or a fact.
05
TASK_INPUT
The briefing and the user request. It cannot rewrite brand truth.

This is the assembled model input, rendered in this fixed order and hashed before the call. Inside the compiled artefact the corresponding delivery slot is named STYLE_TEXTURE; the assembled input the model receives uses GUIDANCE_CONTEXT.

07 / Create

Define the design space. Not the layout.

OBDS holds no pixel coordinates. It holds what a composition is made of, what must never be dropped, what has to keep its distance, and how values combine. A renderer produces one solution inside that space. A validator checks the declared geometry constraints against supplied execution evidence.

01BriefOne product, a headline, a call to action, legal, three formats.
02Design spaceRoles, hierarchy, clear zones, minimum sizes, what may never be dropped.
03CompositionOne valid arrangement per format, chosen by the renderer.
04RenderHTML, PDF, banner, image, video. The renderer is not part of OBDS.
05ValidateGeometry evidence goes back through the same governed truth.

One product, two logos, a headline, a call to action and a legal line. Three formats with different arrangements of the same declared roles. Illustrative compositions, not evidence of an end-to-end renderer integration.

Different layouts. Same governed brand.

OBDS may defineComposition roles, identity hierarchy, clear zones, minimum sizes, measurements, omission priority, never-omit roles, and how two values interact when both apply.
The renderer decidesCoordinates, grid, breakpoints, the typographic scale inside the declared bounds, and which of the valid solutions it produces.
Never brand truthPixel positions, per-format layout templates, capacity tables, HTML, CSS, SVG, renderer code and motion timelines.
Evidence, not opinionThe renderer emits a geometry record for the artefact it produced: canvas, objects, roles, element references and bounding boxes.
visual.min_size
Fails when a selected object drops below the declared minimum. Logo, call to action, legibility.
visual.clear_zone
Fails when another object enters a protected keep-out region.
visual.contains
Fails when an object leaves its declared container or inset. Safe zones.
visual.no_overlap
Fails when selected object sets intersect. Legal, product, call to action, logos.

Four deterministic checks, deliberately no more. Anything richer runs behind a declared, versioned validator. Unsupported geometry fails or routes to that validator. It is never guessed.

OBDS defines the permissible design space. The render layer composes inside it. A validator checks declared constraints against supplied evidence.

08 / Prove

Keep the decision. Not just the output.

In a host implementing the relevant OBDS runtime and rendering capabilities, records capture which approved truth was used. Which rules applied. Which context was assembled. Whether a model was called at all. Why the result was released, blocked or sent to approval. The record is a by-product of the run, not a report written afterwards.

Truth→versioned and canonically hashed
Context→compiled for one declared target
Input→hashed before the model is called
Output→checked by the host after generation
Decision→recorded with its reason
Render→measured against the design space

Canonical hashes prove the approved bytes

One serialisation contract across languages. Duplicate keys are rejected, integers that cannot round-trip are rejected, and 1 and 1.0 hash identically.

Value contracts pin the machine meaning

A structured value binds a shape hash, a schema reference, a schema hash and an optional deterministic validator. Structure and semantics are pinned separately.

Changes are shown before approval

A deterministic change report separates added, changed and removed elements and keeps value, scope, state, validity and contract changes apart.

Every runtime attempt is recorded

Target, artefact hash, assembly hash, model input hash, check results, whether a model was called, and one decision: released, blocked, approval required or failed.

Rendered output is measured, not judged

Geometry evidence carries the boxes that were actually produced. A composition claim fails if a never-omit role is missing, rather than passing vacuously.

Conformance is tested, not declared

A tool may say it uses OBDS concepts. It may only say OBDS conformant once the official suite for that exact version and profile is green and the result is retained.

A decision record is auditable system evidence. It is not cryptographic proof that no other, uninstrumented call happened somewhere else.

09 / Questions

What people ask before they start.

Can I put my brand guidelines in the system prompt?

A prompt carries text, not authority. The model cannot tell whether a paragraph was approved, which market it covers or whether it has expired. OBDS resolves that before the call and compiles only the truth that applies to the declared target at a declared date.

Is OBDS a RAG system for brands?

No. Retrieval answers which information looks relevant. OBDS decides which governed brand truth is authoritative and applicable, and whether the task may proceed at all. The two compose: retrieval narrows the field, OBDS decides what may reach the model.

Does OBDS stop an LLM from hallucinating brand facts?

Not on its own. It limits what reaches the model to approved, applicable truth, and the optional Compiled Runtime blocks the build when required truth is missing, unknown, expired or conflicting. What the model then writes still has to be checked by the host. In SUPABRAND Round 4 neither submission completed a governed end-to-end run (0/20).

Does OBDS make AI output deterministic?

The governance side is deterministic: builds are evaluated against an explicit asOf date, and the governed result hash agrees across languages on 59 of 59 published vectors. The output of the model is not made deterministic.

Is there a LangChain or LlamaIndex integration?

No. No framework adapter has been published or tested. The Python reference runtime receives the model call from the host application as a parameter. An adapter would be an integration built on OBDS, not part of the specification.

Where do I start?

With Foundation, section 26.1 of the specification. Add Compiled Runtime, section 26.2, when a build must refuse to produce anything. The runnable examples show one build that proceeds and one that fails closed.
