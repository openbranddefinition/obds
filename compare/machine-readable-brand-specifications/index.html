03 / Access infrastructure

MCP connects consumers and tools.

MCP is an open access protocol, not a brand specification. Its client/server architecture supports resource and tool access, discovery and invocation. It does not itself decide which brand truth is authoritative or applicable.

Primary sources: MCP introduction and architecture, versioned 2026-07-28 documentation inspected 19 September 2026.

04 / Source notes

Inspect the relevant definitions.

  • BRAND.md specification: Frontmatter, Hierarchy, Layer 4: Governance, and How AI Tools Should Consume BRAND.md.
  • BCP specification: §§5.5, 5.9, 6.3 and 16.2. Draft 0.8; document header 1 September 2026, changelog clarification 2 September. Registry hosting is separate from verification/signing; draft extensions are not mandatory core.
  • MRBS specification: §§03–04, 07 and 09–10. The open specification and BrandCodex registry implementation are distinct.
  • Brando governance properties (v1.3, 22 April 2026) and BGML packaging (0.1). A vocabulary and packaging conventions, not an executable service.
  • OBDS 4.1.3: normative model and optional capability contracts. SUPABRAND Round 4 bounds the execution claim: 0/20 complete pipelines.

Sources can change. Inspection date describes this review; version labels do not imply maturity. Report corrections to lets@killthedragon.com.

05 / Start from the task

Choose by the problem you need to solve.

A readable identity file, a discovery protocol, a governance vocabulary and a task-level applicability contract may be useful together. Decide which responsibilities your integration needs, then inspect the corresponding contracts.

OBDS is useful when a task needs explicit authority, applicability, required truth and fail-closed decision contracts. It does not replace discovery, verify every approved fact or guarantee generated output.
