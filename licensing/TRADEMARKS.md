## 2. Truthful descriptive use

No separate trademark permission is required for a truthful descriptive reference to OBDS where the reference does not imply official status, endorsement or certification.

Examples include:

- "implements OBDS 1.0";
- "supports OBDS 1.0";
- "reads OBDS manifests";
- "writes OBDS manifests";
- "compatible with OBDS 1.0";
- articles, tutorials, talks, research, reviews and comparisons referring to OBDS;
- links to `https://openbranddefinition.org/`.

Descriptive references should use the mark in plain text and should identify the user's own product or organisation more prominently than OBDS.

Permission under this trademark policy does not grant copyright or Commercial Use rights in protected OBDS Materials.

## 3. Descriptive package and repository names

A descriptive compatibility name such as:

- `obds-parser`;
- `obds-validator`;
- `myproduct-obds-export`;

may be used where all of the following are true:

1. the name accurately describes compatibility or technical purpose;
2. it does not imply that the package or project is official;
3. the publisher is clearly identified;
4. no OBDS logo or certification badge is used without permission; and
5. the underlying use of protected OBDS Materials is otherwise permitted.

A name in which an OBDS mark is the leading brand element of a commercial product or service, for example **OBDS Studio**, is not a descriptive compatibility name under this Section.

## 4. Use requiring written permission

Prior written permission is required to:

- use OBDS or Open Brand Definition as, or as the first or dominant element of, a commercial product, service or company name, for example **OBDS Studio**, except for descriptive compatibility names permitted by Section 3;
- use the OBDS logo or project visual identity;
- register a domain name, subdomain or social media handle that implies official OBDS project status;
- use OBDS marks on merchandise;
- imply that an offering is official, endorsed, approved or certified;
- use **OBDS Certified**, **OBDS Certified Partner** or associated badges;
- present a modified specification as an official OBDS specification or official successor.

## 5. Modified specifications

A modified or derivative specification may truthfully state that it was derived from OBDS where the applicable copyright licence permits the modification and attribution.

Unless Kill The Dragon GmbH gives written permission, a modified specification must:

1. use a distinct primary name;
2. state clearly that it is not an official OBDS release;
3. identify material differences where reasonably practical; and
4. not use version numbering or presentation that suggests it is an official OBDS successor.

Names such as **OBDS 2.0**, **Official OBDS**, **OBDS Standard Plus** or equivalent official-looking designations are reserved for use authorised by Kill The Dragon GmbH to the extent permitted by applicable law.

## 6. Certification-related marks

**OBDS Certified**, **OBDS Certified Partner**, associated badges and confusingly similar certification claims may be used only under an active written certification or badge licence.

This policy uses "certified" and related expressions as programme and branding terminology. It does not state that any listed sign is registered as an EU certification mark.

Technical conformance alone does not grant certification rights.

Self-assessed conformance may be described factually as:

"conforms to OBDS x.y, self-assessed"

where accurate.

Self-assessed claims must not use certification badges or imply verification by Kill The Dragon GmbH.
