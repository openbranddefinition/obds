# Task Facts 1.0 suite revision 1 process protocol

This suite is prospective until OBDS 4.1.0 publication. The adopted evaluator CLI is defined in contract section **6** (A-N1 corrected). Tool report metadata below does not change evaluator semantics.

Run Python 3.11+ standard library harness with `--suite SUITE.json --result /tmp/result.json --implementation-name NAME --implementation-version VERSION -- EXECUTABLE [ARG ...]`. The harness appends ordered absolute raw input paths, fixture batch then regression batch, uses no shell and passes no expectations. Input bytes and their hashes must be identical before and after execution. Paths are resolved relative to the suite, never the working directory. Missing official files are infrastructure failures. INVALID is an expected decision, never a skipped case.

Child stdout is exactly one UTF-8 JSON object whose only member is `results`, an array of records with exactly family, caseId, conditionId, snapshotHash, outcome and reason. Duplicate JSON keys, malformed JSON, extra fields, non-string/non-null fields, unpaired surrogates, trailing output and nonstandard numeric constants are rejected. Compare positional records and exact JSON values; never sort, coerce or normalize. Expected fixture records drop only basis. Regression vector inputs are resolved relative to their expectations file and selected by exact suite input path; concatenate expected arrays in suite order. Reject duplicate or missing mappings. Bound/unbound nulls are significant.

Child exit is 2 if any outcome is INVALID, otherwise 0. Crash, signal, timeout and any other exit fail. Preserve raw stdout/stderr with base64 plus readable decoded text and exit code. An I/O failure in a deliberately missing non-suite file yields one unbound INPUT_IO_ERROR and processing continues in argument order; missing official inputs fail before invocation.

Harness exit 0: every comparison, protocol and identity gate passed. Exit 1: conformance mismatch. Exit 2: infrastructure/usage/identity failure. Write a machine-readable result whenever the requested destination is writable, including failure. Reports identify implementation name/version, argv, runtime, executable and script hashes, contract/schema hashes, suite identity, ordered actual records, mismatch details, counts and limitations. No timing or timestamp enters identity. `compare.py --suite SUITE.json --group fixtures --stdout FILE --exit-code 2 --result FILE` verifies retained output with the identical parser/comparator; retained comparison alone does not claim executable reproduction.

Suite identity: collect SUITE.json itself, all identityFiles, contract and schema, all ordered input files and expectation files. Deduplicate relative POSIX paths; sort paths lexicographically; encode each as UTF-8 relative path, NUL, lowercase raw SHA-256 hex, LF. SHA-256 of the concatenated bytes is suiteHash. Store it only in result/registration metadata, not SUITE.json. Implementations and generated results are excluded. Each input hash must match SUITE.json. Contract and schema and expectation hashes must match too. A harness change after first freeze requires a new revision/hash and retention of the old revision; pre-freeze development is not a published revision.

Full Task Facts claims require complete adopted prose/schema behavior and all 66 fixture and 36 regression records, with zero failures/skips/xfails. Schema-only or partial support must be described as such. Separate research Python and Node subjects are not the reference compiler, Foundation, Compiled Runtime, independent certification or production integration. Complete snapshot, conditions, verifier contexts and decisions must be retained; accepted evidence digests do not prove truth.
