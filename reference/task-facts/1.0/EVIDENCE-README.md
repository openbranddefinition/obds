# Evidence boundary and reproduction

The human final-closure decision keeps the entire frozen research and ratification audit trees byte-identical in the non-public audit store. In the working candidate, `EVIDENCE-MANIFEST.json` inventories all 485 historical files under `evidence/interop/` and `evidence/ratification/`. Those historical records and that manifest are excluded from the public archive. Historical path-bearing records are never rewritten or presented as fresh execution.

Two registries answer two different questions, and no path may answer both. A Public Surface Registry entry means the file ships in the public release package and passes the existing package-parity and integrity rules unchanged. A Historical Audit Evidence Registry entry means the file must exist in the preserved non-public audit store and verify there by identity, SHA-256 and byte size; it never means the file ships, and it never substitutes for a fresh public conformance result. `HISTORICAL-AUDIT-REGISTRY.json` is that second registry. It records the role and status of the audit store, binds `EVIDENCE-MANIFEST.json` by its raw digest, and names both the eight classified sources that belong only to the audit store and the twenty-five non-public executable records it holds. The registry and the inventory are themselves excluded from the public archive.

`PUBLIC-EVIDENCE-MANIFEST.json` pins four unchanged evaluator source/schema dependencies at their original relative paths. These are runnable source inputs, not historical audit reports. The public archive contains only these four files under `evidence/`. The complete Task Facts contract, schema, vectors, runner and comparator remain distributed separately, with their frozen suite identity. No frozen Task Facts byte is changed.

The root `OBDS-4.1.0-TASK-FACTS-CONFORMANCE.json` contains fresh Python and Node results: 66 fixtures and 36 regressions per subject, complete captured outputs, exact comparisons and truthful executable/input provenance. `OBDS-4.1.0-FOUNDATION-CONFORMANCE.json` contains the fresh Foundation result. The root package manifest binds their exact bytes. The commands in README.md reproduce the optional results offline using the distributed dependencies; the public archive does not claim to contain or reproduce the separate historical supplementary audit.

Fresh distributable evidence is generated by `tools/build-release.py --run-tests` in a stable neutral workspace, such as `/workspace/obds-release` or `/private/tmp/obds-release`, with Python and Node installed under that workspace or its sibling `obds-release-runtime` directory. Real input and executable paths remain intact. Reassembly accepts those frozen measured reports without rerunning timing-producing tests; it rejects non-neutral provenance and private/local paths. Relocated verification may execute elsewhere but never replaces the public measured reports with its local execution output.

Original research maps to the non-public `evidence/interop/` tree and original ratification to `evidence/ratification/`. Their inventories and historical references remain available to release auditors there; they are not public offline dependencies. Upstream inventory identity is retained in the public source inventory for audit correlation. No production integration claim is made.
