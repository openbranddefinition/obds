# v0.1 → v0.2 targeted contract delta

The supplied independent evaluation returned NOT INTEROPERABLE: 66/66 frozen decisions matched, but 13 counter-probes diverged. This package clarifies those boundaries; it does not claim that a new independent interoperability evaluation has passed.

1. **Routing versus typed validation (B1–B6, B9–B12).** The old recursive family schema made both whole-envelope rejection and per-decision invalidation plausible. Routing now checks only identities, arrays and snapshot presence, followed by uniqueness. Typed validation occurs after binding and canonical hashing. Structural condition errors produce one bound `INVALID / SCHEMA_INVALID`, preserving valid siblings. Structural snapshot/context errors produce bound invalid decisions for every affected condition. Existing semantic type/error codes remain unchanged. Missing context is a bound schema error; a missing snapshot prevents routing. Closed-wrapper errors are also bound when routing is available.
2. **Duplicate routing IDs (B7–B8).** Duplicate case IDs within a family, or condition IDs within any one case, invalidate routing for the entire family: exactly one unbound `INVALID / DUPLICATE_ID`, with null family, case ID, condition ID and snapshot hash. Scan the full routing skeleton before emitting anything; never emit duplicate addressable records or partial family output. Files remain separate routing units.
3. **Raw-input precedence (B13).** Strict JSON parse precedes complete-document TFJ validation, routing, typed validation and applicability. `NaN`/Infinity are `JSON_PARSE_ERROR`; legal JSON floats, unsafe integers and lone surrogates are `NON_CANONICAL_INPUT`. Integer `-0` remains canonical zero and reaches typed validation. Syntax wins even when an earlier token already violates TFJ.

The contract now fixes all six output fields and null filling for unbound records and a uniform CLI results array. Multiple input files are evaluated independently in argument order. These error-binding details remove an additional output-shape gap mentioned in the evaluation.

**No OBDS Core semantics changed. No new predicate capability was added.** Knowledge states, evidence/verification rules, conjunction precedence, associations, temporal behavior and TFJ-0.1 canonical bytes remain unchanged. The package/schema version is 0.2 while the snapshot payload's `contractVersion` remains exactly `0.1`; `"0.2"` in that field is intentionally invalid. This avoids rewriting governed snapshots or attestations.

**All original valid v0.1 frozen hashes remain unchanged.** In fact, all 66 original decision records, including invalid-type decisions and their hashes, match exactly. The six original fixture files and original expected-results file remain byte-identical. The sibling v0.1 package is unchanged. Preservation is checked against the frozen raw digests and literal expectations, not newly generated evaluator expectations.
